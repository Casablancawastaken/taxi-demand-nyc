# Сценарий демонстрации на защите

1. В терминале `python -m pytest -q` → все проверки должны быть зелёными.
2. `streamlit run app.py` → вкладка «Оперативная панель»: факт, прогноз и WAPE; предупредить, что данные синтетические.
3. «Районы и прогноз» → выбрать Midtown Center / Times Sq, другую дату, показать прогноз, карту и экспорт CSV.
4. «Модели и метрики» → назвать SeasonalNaive, Ridge и HistGradientBoosting, 60/20/20 по времени, MAE/RMSE/WAPE.
5. «Объяснение прогноза» → выбрать произвольную зону и дату, показать локальные вклады, две важности, PDP и стабильность по периодам.
6. «Мониторинг» → запустить проверку исходных данных, затем «Смоделировать ухудшение данных»: появится рекомендация переобучения без порчи данных.
7. «Эксперименты и загрузки» → выбрать ID эксперимента и нажать «Воспроизвести»; сверить `matched=true`.
8. В терминале `python -m taxi.cli train` → повторное выполнение без изменения данных возвращает `reused_existing_experiment=true`.
9. `python -m taxi.cli registry` → реестр версий; при необходимости `python -m taxi.cli rollback ВЕРСИЯ` и `python -m taxi.cli forecast`.
10. Прокомментировать ограничение: проверить реальный режим можно только с интернетом и загрузкой датасетов NYC TLC, но в текущем архиве используется деморежим.

## Короткие ответы на частые вопросы

**Что прогнозируем?** Количество начатых поездок жёлтого такси в сутки в каждой зоне отправления NYC TLC.

**Почему NYC?** Официальные открытые исторические данные по поездкам с временными отметками и геозонами.

**Где слабоструктурированные данные?** GeoJSON/SHP с вложенными Polygon/MultiPolygon, которые превращаем в идентификаторы зон и показываем на карте.

**Почему лаговые признаки?** При прогнозе дня t можно знать только день t−1 и раньше. Это предотвращает утечку.

**Откуда 3 модели?** Наивная сезонная база, линейная Ridge, нелинейный градиентный бустинг.

**Как выбрали?** По валидационному WAPE; holdout не участвовал в подборе гиперпараметров.

**Что показывает MAE?** Средняя ошибка прогноза в количестве поездок на зону за день.

**Почему не используем фактическую погоду будущих дней?** Это была бы утечка: её невозможно знать заранее.

**Что, если источник упал?** Есть таймаут, повторные попытки, запись в лог FAILED; имеющиеся данные в SQLite остаются.

**Как реагируем на дрейф?** Следим за PSI лагов и WAPE; рекомендация переобучения при превышении порога, сохраняем запись в журнале.

**Как вернуться к старой модели?** По версии из реестра командой `rollback`, затем пересчёт прогноза.

**Сколько баллов гарантировано?** Никакое количество баллов нельзя гарантировать: преподаватель оценивает работу и защиту, а реальный режим требует проверки на вашей машине.
